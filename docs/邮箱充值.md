# 邮箱登录用户 7702 代付充值流程

## 📋 概述

本文档详细说明邮箱登录用户的 EIP-7702 Gas 代付充值流程。该功能允许邮箱登录用户在没有原生代币（ETH/BNB）的情况下，也能完成链上充值操作。

## 🏗️ 架构总览

```
用户充值流程:
用户外部钱包
    ↓ 转账 USDT
    ↓
Privy 托管钱包 (InVault)
    ↓ 监测余额变化
    ↓ (余额 >= 最小充值额)
触发 EIP-7702 代付交易
    ↓
1. 构建 calls: [approve, deposit]
2. 用户签名 callsSig
3. 签署 7702 authorization
    ↓
发送到后端 API
    ↓
Admin 合约代付 Gas 执行
    ↓
VaultPortal Proxy 充值入口
    ↓
应用内账户余额更新
```

- 调用后端代付 API


1. 转换充值金额 (parseUnits)

5. 构建 calls 数组
6. 生成 userHash
7. 用户签名 callsSig
8. 签署 7702 authorization

### 4. **useProcess7702Delegated Hook**

**文件位置**: `src/hooks/useProcess7702Delegated.ts`

**功能**:

- 检查用户地址的 7702 委托状态
- 自动发起授权交易（如果未授权）
- 轮询等待授权确认
- 本地缓存授权状态（1小时有效期）

**工作原理**:

1. 检查 localStorage 缓存
2. 如果缓存有效且已授权，直接返回 true
3. 否则查询链上委托状态
4. 如果未授权，发起授权交易
5. 轮询等待授权确认（最多60次，每5秒一次）
6. 更新缓存

## 🔑 关键配置

### **1. 合约地址配置**

需要在 `depositConfig` 中配置以下地址：

```typescript
{
  chainId: 56,                          // BSC 主网
  tokenAddress: "0x...",                // USDT 合约地址
  vaultAddress: "0x...",                // VaultPortal Proxy 地址
  adminAddress: "0x...",                // Admin 合约地址（代付执行者）
  logicalAddress: "0x...",              // Logical 合约地址（7702 委托目标）
  minDeposit: "10",                     // 最小充值额
  decimals: 18,                         // 代币精度
}
```

### **2. API 端点配置**

后端代付 API 地址：

```typescript
url: "/api/deposit"; // 或实际的后端 API 地址
```

## 📊 性能优化

### **1. 余额轮询优化**

- 当前: 5秒轮询一次
- 优化: 可以根据网络情况调整间隔
- 建议: 开发环境 3秒，生产环境 5秒

### **2. 缓存优化**

- 7702 授权状态缓存 1 小时
- 避免重复的链上查询
- localStorage 持久化

### **3. 错误重试**

- wagmi useBalance 自动重试 3 次
- 7702 授权轮询最多 60 次（5分钟）
- 建议: 添加超时提示

---

## 🔐 安全注意事项

### **1. 防重放攻击**

- userHash 包含 nonce、chainId、adminAddress
- 每次交易 nonce 递增
- 跨链隔离

### **2. 签名验证**

- 用户签名 callsSig
- 7702 授权签名 authorization
- 后端二次验证

### **3. 授权额度**

- approve 使用 maxInt256
- 一次授权，多次使用
- 减少交易次数

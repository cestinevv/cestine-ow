# Sentry 健康报告（领导向 PDF）

## 怎么跟 Agent 说（给人看）

点名：`@sentry-health-report`。也可以不点名，直接说「出一份生产/测网报告」。Sentry MCP 要已连接。交付只有当前用户桌面上的 PDF。

| 你想要的 | 可以这样说 |
|---|---|
| 刷新生产（默认） | 再出一份生产环境问题汇总，覆盖桌面 PDF。 |
| 测网 | 出一份测网 testenv 报告，打到桌面。 |
| 近 7 天 | 出一份生产报告，最近 7 天。 |
| 从某天到现在 | 出一份生产报告，从 8 月 18 日到现在。 |
| 不要抖音对照 | 出一份生产报告，不要抖音对照。 |
| 两份对比 | 按当前 skill 再拉一份生产 PDF，我跟测网那份对比。 |

不说时间 = **有数据以来 → 现在**，不是近 7 天。不说环境 = **生产**。测网必须说测网 / testenv / 测试环境，不要说 `test` / `staging`。

不要用来：查单条 issue、改代码、要 Markdown / 飞书文档。

## 组织 / 项目（不要写死 slug）

**禁止**把 Sentry `org` / `project` slug、产品展示名写进本 skill 当常量。改名、换项目后 skill 应仍然能跑。

每次执行第一步：从**当前会话已连接的 Sentry MCP** 解析 `org`、`project`（whoami / find_projects / 工具默认约束）。用户**不必**报项目名。

| MCP 里有几个项目 | 怎么做 |
|---|---|
| 1 个 | 直接用它 |
| 多个 | 用户说了名字/slug 就用那个；没说则用 MCP 当前默认项目，并在回复里点明用了哪个 |

PDF 标题和桌面文件名用 MCP 返回的**项目展示名**（没有展示名再用 slug）。生产：`{展示名}生产环境问题汇总-YYYY-MM-DD.pdf`；测网：`{展示名}测网环境问题汇总-YYYY-MM-DD.pdf`。

## 对用户暴露的参数

| 键 | 默认 | 谁来说 |
|---|---|---|
| days | **不设** | 用户可选：近 N 天 / 从某日到现在 |
| env | `production` | 用户说测网 / testenv / 测试环境 → **`testenv`**（Vite `MODE`，不是 `test` / `staging`） |
| compareDouyin | `true` | 用户说不要对照时关掉；测网默认仍开，但正文标明对照是实验室量级 |
| output | 见上表桌面文件名 | 一般不问 |

测网与生产 **共用同一个 Sentry 项目**，必须带 `environment:{env}`。禁止不带 environment 查全项目（测网验证抛错会混进生产数字）。

包未发到生产、用户要看 0.3 字段（`api.failure` / `net.*` / `perf_type`）时：先拉 **`testenv`**，不要假装生产已有这些 tag。

## 统计时段（默认 ≠ 近几天）

| 用户怎么说 | 实际窗口 |
|---|---|
| **不说时间**（刷一下 / 更新 / 重拉） | **有数据以来 → 现在**：该环境最早一条错误 → 本次拉取时刻。不是「近 7 天」。 |
| 「最近 3 天 / 近一周」 | **从本次拉取时刻往回 N 天** → 现在。若这段里还没有那么早的数据，起点改成最早一条错误。 |
| 「从 8 月 18 日到现在」 | 用他说的日历日，再和最早错误取较晚者。 |

其它口头覆盖：「不要抖音对照」关对照；默认仍拉失败 + 慢接口 + 体验。

数据够长之后若「不说时间」会拉出几十天、报告太噪，再把默认改成近 7 天；**现在不要改**。

### 统计时段算法（强制）

```text
end   = 本次拉取的北京时间
start = 用户指定起点（近 N 天则 now-N；或明确日期）
        若用户未指定 → 该环境最早一条错误时间
actualStart = max(start, 该环境最早一条错误时间)
芯片上只写 actualStart — end，禁止写「近 7 天」这种可能比真实窗口更长的口号
```

Sentry 查询 `period` 取能盖住 `actualStart` 的最小档（`24h` / `7d` / `14d` / `30d` / `90d`），数字以查询结果为准，不以档名当标题。

## 何时不要用

- 查单个 issue 根因、改代码、配告警规则
- 要 Markdown / HTML / Canvas / 飞书文档当交付物

## 交付硬约束

- **只输出桌面 PDF**。排版用临时 HTML（`/tmp` 或系统临时目录），Chrome `--print-to-pdf`，打完立刻删 HTML。
- **禁止**写入仓库 `docs/reports/`、禁止留下 `.html` / Canvas。
- 桌面路径按**当前机器**解析，不要写死 `/Users/...`：macOS / Linux 用 `$HOME/Desktop`；Windows 用 `%USERPROFILE%\Desktop`（或 PowerShell `[Environment]::GetFolderPath('Desktop')`）。
- 打开方式：macOS 用 Preview；Windows 用默认 PDF 阅读器（`start`）。不要让用户用 Cursor 内置 PDF 预览当验收。
- Chrome 可执行文件同样按系统找：macOS 为 `Google Chrome.app`；Windows 常见为 `C:\Program Files\Google\Chrome\Application\chrome.exe`。当前这份 skill 的示例命令以 macOS 为主，换 Windows 时只换路径，版式不变。
- 正文给领导看：禁止「一句话版」「本页不含决策行动项」「给非技术同学」等元废话。
- **版式以 8 月 24 日那份为底**：标题 + 芯片 + 数据来源 + 怎么读 + 汇总结论 + 三卡 +「一、错误在报什么」+ 偏慢接口表 + 网络双饼图（**仅当有 `net.effective_type`**）+ 请求失败表 + 前端异常表 +「二、页面体验」。
- **禁止**主指标用「未解决问题数」（观测期会误导）。
- **禁止** TTI / TBT（现场不采；领导不关心）。可写 INP（点了之后有反应）。
- 三卡沿用旧口径：发生次数 / 涉及用户 / 接口偏慢占比。饼图把「偏慢 + 请求失败」画在一起；表里分清：偏慢是已经成功只是慢，请求失败是没有成功返回。
- 体验约 5% 用户，表头必须写清。体验对照：我们=橙色，对照方=灰色；条越长越慢。
- 口径相对上一份生产 PDF 变了时，回复里写清差在哪（例如多了一段网络情况）。
- 链上 / 钱包 `reportError` **尚未作为独立一类**：业务 catch 没接到之前，不要空查「链上失败」切片。
- 数据来源一段只写从哪来、怎么读，**禁止**「打开原始列表」或任何 Sentry Issues 总列表链接。前端异常行内的单条 Issue 短链可保留。

## 网络情况（强制：只画网速构成，不画离线）

领导稿**不要**展示 `net.offline` / 「离线 / 未记成离线」。这个标记 = 浏览器认为当前没网；空着是常态，画成 0% vs 100% 没有信息量，还容易读成「漏采」。

要画的是 **`net.effective_type`（4g / 3g / 2g / 未标注）**：

- 只在失败、超时、偏慢、主动上报这些请求上有
- **未标注** = 这次没采到网速，常见是浏览器不支持 Connection API（Safari 等），不是「用户没网」
- 图例 `名称 n（约 xx%）`；结尾：只能当旁证，不能定责 CDN

版式：偏慢表下面最多两张饼图——左：偏慢请求的网速；右：网络中断请求的网速。不要再复制一块网络说明。禁止「自称在线 / 未记成离线」。

**没有网速数据就不要画空饼图**：`net.effective_type` 全空（常见于生产尚未升采集包）时，整段网速图省略，改写一句「本环境还没有网速标记」。不要画 100%「未标注」。

## 请求失败怎么命名

标题用 **「请求失败」**。块首饼图（分母=四类之和）+ 图例带占比 + 一句定义。表含占比。表下只保留 401/取消/大部分 4xx 不上报，**不要**再解释离线。

| 类型 | 定义（给领导看） |
|---|---|
| 网络中断 | 请求发出去，传输断了，没拿到回包 |
| 请求超时 | 发出去了，等满超时时间（约 60 秒）还没回来 |
| HTTP 500 | 服务器返回了 5xx |
| 业务码失败 | HTTP 是 2xx，但业务结果是失败 |

怎么读（开头必须有）：发生次数 / 涉及用户 / 偏慢 vs 请求失败 / **未标注**（没采到网速，常见是浏览器不支持 Connection API）/ **页面加载采样**（约 5% 会话，看打开有多慢，不是每一次接口告警；第二节表用这个）。不必为了报告把采样调到 10%。

## 前端异常怎么写

在旧表「局部 / 接口级」红橙标记上，加「大概原因」列。不要拿掉分级。

列：`问题` | `大概原因` | `次数 / 用户` | `影响范围`（pill：局部=红、接口级=橙、可忽略=绿 + 出现在哪）。

- 问题用产品语言；Issue 短链放标题下。禁止 JS 原文当标题。禁止在标题旁写 Replay。
- 大概原因一句表象，不写修复方案。对照：

| 原始信号 | 问题 | 大概原因 |
|---|---|---|
| Hydration Error / replay_hydration_error | 首屏水合不一致 | 服务器和浏览器第一次画出的结构对不上 |
| `dispatch` 空指针、播放器 chunk/资源 | 播放器空指针 / 资源没加载上 | 播放器还没就绪，或脚本/片源没拉下来 |
| `x.map is not a function` | 列表渲染失败 | 接口没返回数组，页面仍按列表去画 |
| `is not defined` | 页面脚本缺变量 | 引用了不存在的名字，多半是打包或作用域 |
| `API business` | 业务操作被拒绝 | 接口 HTTP 成功，但业务码失败 |
| HTTP 5xx | 服务端报错 | 接口自己返回了 5xx |

Replay 水合若不在 errors 总量里：表里仍写，并注明「未计入上方告警次数」。不要写 Replay 字样。

## 流水（按序）

1. 从 Sentry MCP 解析当前 `org` / `project` / 展示名（不要用 skill 里的旧 slug）。再解析 env / days / 对照。取北京时间 `end`。测网必须 `environment:testenv`。
2. 查该环境最早、最晚错误时间，算出 `actualStart — end`。
3. **分开拉、分开写**：
   - 失败总量：`api.failure` 有值的 + 前端崩溃（无 `api.failure`、也无 `perf_type:slow_api`）。含 `count()`、`count_unique(user)`。
   - 慢接口总量：`tags[perf_type]:slow_api`（成功但慢，level 多为 warning）。不要写裸 `perf_type:slow_api`。
   - 标题匹配只作旧事件兜底。
4. 饼图沿用旧口径：接口偏慢 + 网络中断 + 超时 + 前端/业务/HTTP（分母=告警总次数）。偏慢接口表、请求失败表、前端异常表分开写。Top 慢接口按归一化路径归并。
5. 网络：有 `net.effective_type` 才画 4g/3g/未标注饼图（可加一张「中断时的网速」）。全空则省略。不要画离线。请求失败：构成饼图 + 定义 + 表（含占比）。表下只写 401 等不上报。
6. 按页面汇总告警次数（可含偏慢）；**柱状图只画 Top 5**（最高页为 100%）。次数高但用户极少时必须写清「少数人反复打」：已在 Top 5 的标在该行；没进 Top 5 的用图表下方**一行说明**，不要再画几乎看不见的细柱（细柱容易被当成「第六名页面」，真正要强调的是「人很少、别把次数读成大面积」）。
7. 体验：LCP / FCP / TTFB / CLS / INP（P75）；首页采样请求的平均 / P95 / 采样次数。抖音实验室对照沿用 `reference.md` 里的既定数字，除非用户要求重测。
8. 生成 PDF 到桌面并用 Preview 打开。回复只说：文件路径、环境、时段、相对上一版的关键变化（若有）。

查询字段、章节骨架、对照数字、降噪口径见 [reference.md](reference.md)。
